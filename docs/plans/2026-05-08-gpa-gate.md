# Deterministic GPA Threshold Gate

**Date**: 2026-05-08
**Status**: Implemented (lint-clean, 56 unit tests for the gate, 13 for chair overrides)
**Trigger**: Admission committee meeting 2026-05-08 — committee flagged that the agent does not consistently enforce the SPE GPA threshold, lets motivation/reference signals override below-threshold GPAs, and treats GPA computations as if they were a soft signal.

## Problem

Today the threshold check is 100% LLM-driven through prompt instructions:

> "If the candidate's GPA is BELOW this threshold, academic_strength should be at most 5."
> *(prompts.py:53-57, Academic Evaluator system prompt)*

To apply this rule the LLM has to (1) parse a free-text GPA, (2) parse a free-text threshold, (3) know the direction of each grading system (German 1.0 = best, all others higher = better), and (4) actually enforce the cap. It fails inconsistently, especially across grading systems. Worst offenders: Italian /30 (no rules in the prompt at all), German 1-5 (inverted scale), UK classifications (categorical not numeric).

Secondary issues confirmed during the meeting and codified in this branch:

- **No programmatic clamp.** Even when the LLM does cap academic_strength at 5, the Chair re-scores in synthesis from scratch and can come back with 7.
- **No hard reject.** A below-threshold candidate could still receive `accept` if the LLM weighed motivation/letters heavily enough.
- **GPA confidence ignored.** The extractor returns `confidence ∈ [0,1]` but no downstream code consumes it. Image-only / OCR-garbled transcripts get treated identically to clean ones.
- **Italian retake inflation.** The committee explicitly notes that Italian averages are inflated by retakes, which is why Bologna/Polimi use 28 and Sapienza 29. Not in the prompt, not in the gate parser.
- **EPFL-internal candidates use a different rule.** Algebra+analysis average against 4.5 (or 4.0 for section-switchers), not overall GPA. The flat `GpaExtraction.gpa_value` cannot represent this.

## Design

### Module: `agents/gpa_gate.py`

Pure-Python, no LLM. Public surface:

```python
class GradingSystem(Enum):  # 8 systems + UNKNOWN
    US_4, SWISS_6, FRENCH_20, GERMAN_1_5, ITALIAN_30, INDIAN_10, PERCENTAGE, UK_CLASS, UNKNOWN

class ThresholdDirection(Enum):
    BELOW, NEAR, ABOVE, UNKNOWN

@dataclass(frozen=True)
class ThresholdVerdict:
    direction: ThresholdDirection
    gap: float                     # signed; positive = better than threshold
    confidence: float              # parser confidence
    system: GradingSystem
    extracted_value: float | None
    threshold_value: float | None
    notes: tuple[str, ...]

    def to_prompt_line(self) -> str: ...

def detect_grading_system(scale_hint: str, value_hint: str = "") -> GradingSystem: ...

def compare_to_threshold(
    *, gpa_value: str, gpa_scale: str, threshold: str, school_name: str = ""
) -> ThresholdVerdict: ...

def epfl_internal_value(per_subject: dict[str, float] | None) -> str | None: ...
```

Parsers per system, with named numeric ranges (`_US_MIN/MAX`, `_ITALIAN_MIN/MAX`, ...). All bounded — out-of-range values return `None`. The dispatch table `_SYSTEM_RULES` maps each system to its `parser`, `higher_is_better` (only German is `False`), `near_window`, and a human-readable `label`.

### `30 e lode` handling

Italian transcripts can show distinction marks: `30 e lode`, `30L`, `30 cum laude`. The parser maps these to `30.5` so a "30 e lode" candidate strictly compares above a "30" threshold. Implemented inside `_parse_italian_30`; covered by tests.

### Gap sign convention

Across grading systems, `verdict.gap > 0` always means "better than threshold". For higher-is-better systems this is `extracted - threshold`; for German (lower-is-better) it is `threshold - extracted`. This means downstream code can do `if v.gap < 0: reject` regardless of system.

### Detection priority

`compare_to_threshold` resolves the system in this order:

1. Parse the SPE threshold string with each system's anchor regex (`/20`, `/30`, etc.) — SPE chooses the scale, so it's the most reliable signal.
2. Fall back to the candidate's `gpa_scale` field.
3. Fall back to a numeric range ladder over the candidate's value (3.5 → US_4, 5.3 → SWISS_6, etc.).

If neither side parses cleanly the verdict is `UNKNOWN`.

### EPFL-internal: per-subject value

`epfl_internal_value(per_subject)` returns the algebra+analysis average when both subjects (or just one) appear in the extracted `per_subject_averages` dict. `run_evaluation.py` calls it for EPFL-internal candidates and feeds the result to `compare_to_threshold` instead of the overall GPA. Falls through to overall GPA when the extractor didn't populate the field.

### Pipeline wiring

Three insertion points in the existing flow:

1. **`run_evaluation.py` — pre-orchestration.** After `extract_gpa`, call `compare_to_threshold` (with the EPFL-internal value when applicable) and inject the result as a header section in the transcript:

   ```
   ## GPA Threshold Verdict (deterministic)

   - Compared value: 4.25 (algebra+analysis average (EPFL-internal rule))
   - GPA THRESHOLD VERDICT: BELOW (extracted 4.25 vs threshold 4.5,
     gap -0.25, system=swiss_6, confidence=90%)
   ```

   The Academic Evaluator now consumes a structured fact instead of doing arithmetic.

2. **`orchestrator.py` — post-Phase-1, pre-Chair.** Call `clamp_academic_strength_below_threshold(scorecards, ...)`. When the verdict is BELOW with sufficient confidence, the Academic scorecard's `academic_strength` is capped at 4. The Chair sees the capped value during synthesis, which keeps its reasoning consistent with the final decision.

3. **`chair.py` — post-synthesis.** Call `apply_gate_overrides(...)` after the LLM produces `ChairSynthesis`. Two policies:

   - **Confidence gate**: `gpa_confidence < 0.5` → force `WAITLIST`. Image-only or OCR-garbled GPAs go to manual review rather than auto-reject.
   - **Hard reject**: verdict `BELOW` with sufficient confidence → force `REJECT` regardless of what the Chair said.

   Override events are logged with the original-vs-final decision pair for audit. The audit string (e.g. `"GPA below SPE threshold (extracted 3.65 vs 4.0, gap -0.35) — hard-reject by gate."`) is appended to `cons` so it surfaces in the dashboard.

### `GpaExtraction` model extension

Two new fields, both with sensible defaults so existing constructors keep working:

```python
per_subject_averages: dict[str, float] = Field(default_factory=dict)
"""'analysis', 'algebra', 'mathematics', 'physics', 'computer_science', ..."""

section_switch_detected: bool = Field(default=False)
"""True when the transcript shows mise-à-niveau / section change."""
```

The extractor prompt has new sections: an Italian rules block (lode handling, retake inflation caveat, thesis-grade exclusion), a per-subject-averages block (with explicit instructions to populate `analysis` + `algebra` for EPFL-internal transcripts), and a section-switch detection block.

## Behavioural guarantees

1. **Below-threshold = hard reject.** Confirmed by `test_below_threshold_forces_reject`. The Chair cannot override.
2. **Low confidence = waitlist.** Confirmed by `test_low_confidence_routes_to_waitlist` and `test_low_confidence_overrides_below_threshold`. Image-only transcripts go to humans.
3. **No silent data loss.** Every override appends a one-line audit string to `cons` and emits a `logger.info` event with the original-vs-final decision pair.
4. **Pure-Python parsing.** The gate has no LLM dependency; failures are deterministic and reproducible from logs.
5. **EPFL-internal uses algebra+analysis average** when the extractor populates `per_subject_averages`. Falls back to overall GPA when not (no breakage, just less precision).

## Edge cases that DO go through

- **NEAR verdict**: not auto-rejected; the LLM's decision stands. NEAR cases are exactly where the committee discusses borderline candidates.
- **UNKNOWN verdict**: not auto-rejected; same as before the gate existed. Logged so we can backtest detection-failure rates.
- **No SPE threshold**: not auto-rejected. UNKNOWN system, no clamp, no override.
- **External candidate with no letters**: still uses `EXTERNAL_PROFILE` renormalised (from the previous branch), independent of the gate.

## Backtesting

Once this lands, re-run `run_evaluation.py` over the historical labelled set and:

1. Expected: previously-accepted candidates with sub-threshold GPAs flip to `reject`. These are the false-accepts the committee was concerned about.
2. Expected: agreement rate with `decision_final` should rise on `reject` cases (mechanical rule = mechanical agreement).
3. Watch for: agreement drops on `accept` cases. If the gate is too strict (e.g. NEAR cases that the committee actually pushed through), surface them and discuss raising the NEAR window.
4. New metric: count of `WAITLIST` outcomes triggered by low confidence. Compare to OCR quality of those transcripts — most should be image-only PDFs.

## What this does NOT cover

- **Override mechanism** (e.g. exceptional candidate, top-2% claim from Dean's letter). User explicitly chose hard-reject; no override path. If the committee wants an exception they grant it manually outside the agent.
- **Per-university bar tweaks** (Sapienza 29 vs Bologna 28). The gate honours whatever threshold SPE provides; if SPE wants to lower Sapienza to 28, that's a parquet edit, not a code change. Action item from the meeting.
- **Web research / Perplexity tooling.** Separate concern.
- **Italian grade re-deflation.** The committee explicitly told me NOT to deflate Italian averages — the threshold accounts for retake inflation.
- **GPA value ranges per institution** (e.g. flagging `5.7/6` from EPFL as suspicious because EPFL caps at 6.0). Out of scope; covered by the existing `gpa_normalized` clamp.
